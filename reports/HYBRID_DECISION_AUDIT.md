## 3. Central question — is useful ML evidence discarded?

**No.** Of the 1,164 rows where rules abstain:

- rows with ML real-class top label at any probability ≥ 0.45: **0**
- rows with ML real-class top label at ≥ 0.80: **0**; at ≥ 0.90: **0**; at ≥ 0.95: **0**

On every single rules-abstain row, the ML model's most probable class is itself `unclassified` (median probability 0.9997). The engine's Case B (`ml_only`/ML-only classification) is **structurally unreachable** on this model snapshot because it requires `ml_prediction != unclassified`, which never occurs where rules abstain.

**Conclusion:** No reclassification gain is achievable by tuning the hybrid thresholds on this model + dataset. The 1,166 "unclassified" outcomes are driven by (a) spatial-evidence sparsity (1,164/1,268 have no labeling-function trigger), and (b) a weak-supervision XGBoost model that learned to emit the majority/abstention class on no-evidence feature rows. The improvement opportunity is **semantic honesty + decision policy**, not classification inflation.

## 4. Root cause of the flagged semantic contradiction

The stored snapshot (produced by a pre-fix engine) reports, for **all 1,166 unclassified rows**:

- `hybrid_confidence` ≈ 0.9997 (min 0.6516, p50 0.9997) → rendered as **"high"** confidence
- `confidence_level` = high (1,164), medium (2)
- `risk_score` ≈ 99.8

That is the flagged contradiction: a *final decision* of `unclassified` carrying ~99.97% "hybrid confidence" and "high confidence level". Confusion chain: `raw_ml_confidence` (probability of the abstention output class) was conflated with final-decision confidence; the risk/confidence tiers were computed on that conflated number. The live presentation layer was already corrected earlier (abstention → `confidence_score: null`, `confidence_level: insufficient_evidence`, `decision_status: uncertain`); the stored artifact still contains the pre-fix values and will be regenerated by `--force`.

## 5. What this implies for the decision policy

- Case B (rules abstain + strong ML) must be **provisioned with a justified threshold** and honestly reported as unreachable on the current snapshot (0 eligible rows at ≥ 0.80). It is a forward-compatibility capability, not an inflation lever.
- Conflict handling (Case D) currently "picks the dominant source" even at ~0.50 ML probability. Policy change: genuine strong disagreement → UNCERTAIN + review; contested-but-strong single-source → PROBABLE + review; true close ties → UNCERTAIN.
- `agreement` should mean positive agreement on a real class, not reciprocal abstention.
- Internal/presentation semantics must expose `classification_status` (confirmed/probable/uncertain) separate from model probability (`ml_probability`), rule strength (`rule_vote_strength`), and decision confidence tier.
